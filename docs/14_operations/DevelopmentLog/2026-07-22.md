# 오늘 작업

MDE Knowledge Plugin v1의 Source 등록, Markdown/Obsidian 스캔, SQLite 색인, 검색, 태그, 백링크, 증분 스캔, CLI와 테스트를 구현했다. 실제 사용자 전역 위치에 `mde-docs` Source를 등록하고 86개 문서 스캔과 `workflow` 검색 스모크 테스트를 완료했다. Source 생명주기와 스캔 결과를 개인정보 노출 없이 기록하는 v1.1 감사 로그를 추가했다. 실제 증분 스캔에서 변경 문서 12개를 반영한 뒤 재스캔에서 90개 문서가 모두 Unchanged임을 확인했다. uv 0.11.30을 사용자 로컬에 설치하고 PATH를 복구하여 `uv run mde` 실행을 검증했다. 사용자가 선택한 30일 감사 로그 자동 보존 정책을 v1.2로 구현하고 실제 사용자 로그에 적용했다. Knowledge Plugin의 등록·스캔·검색·태그·백링크·보안·감사 로그 사용 절차를 `CMD-003` 상세 사용자 가이드로 저장했다. MDE 전체 사용자 가이드 `CMD-004`와 실제 CLI parser 기반 `mde docs check`, 변경 미리보기, 명시적 승인 적용 기능을 구현했다. `knowledge-guide` target도 추가하여 전체 가이드와 Knowledge 상세 가이드의 명령 참조를 독립적으로 동기화하고 144개 전체 테스트를 통과했다. `autoknowledge-vault`를 개인 민감 Source로 등록하고 Markdown 18개 첫 스캔, Source 제한 검색, 18개 Unchanged 재스캔, 기본 검색 제외, 감사 로그 경로 비노출을 확인했다.

# 문제점

uv 실행 파일이 PATH에 없었고 저장소 전체 Ruff 검사에 외부 임시 폴더 권한 오류와 기존 린트 오류가 있었다. 실제 스모크 테스트에서도 uv 명령을 직접 사용할 수 없었다. 문서 전체 자동 생성은 사람이 작성한 설명을 덮어쓸 위험이 있었다.

# 해결

설치된 Python 3.12 환경의 동일한 `mde.cli` 진입점으로 검증하고 외부 임시 폴더를 제외했으며 기존 린트 오류 3건을 최소 수정했다. Source Registry와 SQLite가 `C:\Users\<user>\.mde\knowledge`에만 생성되고 프로젝트 내부에는 생성되지 않음을 확인했다. 공식 Astral 사용자 로컬 설치 프로그램으로 uv를 설치하고 `C:\Users\<user>\.local\bin`을 사용자 PATH에 추가했다. 문서 자동화는 관리 표식 사이만 수정하고 기본적으로 diff만 표시하며 `--apply`가 있어야 적용되도록 제한했다.
