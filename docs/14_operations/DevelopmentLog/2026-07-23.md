# 오늘 작업

프로젝트별 사용법 문서를 `docs/15_projects/<project>/usage/`에서 관리하도록 표준과 새 프로젝트 생성 템플릿을 확장했다. AutoKnowledge Lite에 사용법 진입 문서를 추가하고 개인 Vault에 6개 카테고리 안내 폴더를 생성했다. 프로젝트 생성 집중 테스트 19개와 전체 회귀 테스트 144개를 통과했고, 개인 Source 증분 스캔과 기본 검색 제외를 확인했다. Windows CP949 콘솔에서 Knowledge 검색 결과의 미지원 Unicode 문자 때문에 발생하던 출력 중단을 수정하고 CP949·UTF-8 회귀 테스트를 추가했다. 전체 테스트 146개와 Ruff·formatter 검사를 통과했다. 남아 있던 로컬 미추적 항목을 분석해 에이전트 작업 영역, 의존성, Android 생성물, 실행 데이터, 개인 Vault 복구본으로 분류하고 안전한 Git 제외 규칙을 추가했다. 전체 테스트 146개와 정확한 `ruff check .`를 통과했다.

# 문제점

프로젝트 공식 설계·구현·테스트·사용법과 개인 학습·생활 자료의 저장 경계가 명확하지 않았고, 기존 개인 노트를 일괄 이동하면 링크와 Git 이력이 깨질 위험이 있었다. 표준 Ruff 명령이 로컬 의존성 폴더 `.test-deps`까지 검사해 외부 패키지 오류 442건을 보고했다. CP949 stdout이 em dash를 인코딩하지 못해 색인과 검색이 성공한 뒤 CLI 출력에서 `UnicodeEncodeError`가 발생했다. 재생성 가능한 파일과 개인·복구 자료가 Git 상태에 함께 나타나 실제 소스 변경을 식별하기 어려웠다. 전체 formatter 검사는 이번 변경과 무관한 기존 Python 파일 52개의 포맷 부채를 보고했다.

# 해결

프로젝트 공식 기록은 프로젝트 문서 트리에 유지하고 개인 Vault는 같은 개인 보안 경계 안에서 폴더로만 분류하도록 결정했다. 기존 `AutoKnowledge/` 노트 17개는 이동하거나 수정하지 않고 SHA-256 일치로 보존을 확인했다. Ruff는 `.test-deps` 제외 검사와 변경 파일 포맷 검사로 이번 변경이 통과함을 분리 검증했다. Knowledge CLI는 stdout 인코딩을 유지하면서 미지원 문자만 `?`로 대체하도록 설정해 원본과 색인에 영향을 주지 않고 출력 중단을 방지했다. 실제 `PYTHONIOENCODING=cp949:strict` 검색과 전체 회귀 검증에서 종료 코드 0을 확인했다. 로컬 생성물은 경로를 제한해 Git에서 제외하고 Android 실제 소스는 향후 추적 가능하게 유지했으며 모든 기존 파일을 보존했다. 기존 52개 Python 파일은 범위 밖이라 자동 포맷하지 않고 테스트 기록에서 기존 저장소 문제로 구분했다.
