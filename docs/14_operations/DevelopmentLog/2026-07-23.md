# 오늘 작업

프로젝트별 사용법 문서를 `docs/15_projects/<project>/usage/`에서 관리하도록 표준과 새 프로젝트 생성 템플릿을 확장했다. AutoKnowledge Lite에 사용법 진입 문서를 추가하고 개인 Vault에 6개 카테고리 안내 폴더를 생성했다. 프로젝트 생성 집중 테스트 19개와 전체 회귀 테스트 144개를 통과했고, 개인 Source 증분 스캔과 기본 검색 제외를 확인했다. Windows CP949 콘솔에서 Knowledge 검색 결과의 미지원 Unicode 문자 때문에 발생하던 출력 중단을 수정하고 CP949·UTF-8 회귀 테스트를 추가했다. 전체 테스트 146개와 Ruff·formatter 검사를 통과했다. 남아 있던 로컬 미추적 항목을 분석해 에이전트 작업 영역, 의존성, Android 생성물, 실행 데이터, 개인 Vault 복구본으로 분류하고 안전한 Git 제외 규칙을 추가했다. 전체 테스트 146개와 정확한 `ruff check .`를 통과했다. AutoKnowledge Lite의 전체 Python·Android 구현을 별도 런타임 저장소에서 `apps/autoknowledge-lite/`로 통합하고 공식 자동 시작 경로를 전환했다. 앱 Python 테스트 30개, Android 단위 테스트·Debug 빌드, MDE 회귀 테스트 146개와 Ruff 검사를 통과했다. AutoKnowledge Lite v0.2.0에 Android 고정 Vault 폴더 선택, 기본 Inbox, 서버 경로 허용 목록, 선택 폴더 저장과 단일 파일 Git 동기화를 추가하고 프로젝트 설계·API·UI·구현·테스트·사용법·릴리스 문서를 작성했다. 앱 테스트 52개, Android 단위 테스트와 Debug APK 빌드, MDE 회귀 테스트 146개, Ruff와 앱 formatter 검사를 통과했다. 휴대폰 Tailscale 주소에서 v0.2.0 APK를 직접 내려받는 고정 API를 추가하고 전체 앱 테스트 54개와 실제 다운로드 SHA-256 일치를 확인했다.

# 문제점

프로젝트 공식 설계·구현·테스트·사용법과 개인 학습·생활 자료의 저장 경계가 명확하지 않았고, 기존 개인 노트를 일괄 이동하면 링크와 Git 이력이 깨질 위험이 있었다. 표준 Ruff 명령이 로컬 의존성 폴더 `.test-deps`까지 검사해 외부 패키지 오류 442건을 보고했다. CP949 stdout이 em dash를 인코딩하지 못해 색인과 검색이 성공한 뒤 CLI 출력에서 `UnicodeEncodeError`가 발생했다. 재생성 가능한 파일과 개인·복구 자료가 Git 상태에 함께 나타나 실제 소스 변경을 식별하기 어려웠다. 전체 formatter 검사는 이번 변경과 무관한 기존 Python 파일 52개의 포맷 부채를 보고했다. 실행 가능한 코드는 별도 `.runtime` Git 저장소에 있고 모노레포 앱 경로에는 골격만 있어 코드와 공식 문서의 단일 원본이 달랐다. 첫 앱 환경 동기화와 Windows 예약 작업 전환은 초기 의존성 로딩 때문에 시간 제한이 발생했고, 전체 formatter는 기존 52개 파일의 포맷 부채를 다시 보고했다. 첫 폴더 선택 API 테스트에서 요청의 선택값이 저장 레코드로 전달되지 않는 결함을 발견했고, 저장소 루트에서 앱 가상환경의 pytest를 실행한 최초 명령은 앱이 아닌 MDE 테스트까지 수집해 PyYAML 누락 오류를 보고했다.

# 해결

프로젝트 공식 기록은 프로젝트 문서 트리에 유지하고 개인 Vault는 같은 개인 보안 경계 안에서 폴더로만 분류하도록 결정했다. 기존 `AutoKnowledge/` 노트 17개는 이동하거나 수정하지 않고 SHA-256 일치로 보존을 확인했다. Ruff는 `.test-deps` 제외 검사와 변경 파일 포맷 검사로 이번 변경이 통과함을 분리 검증했다. Knowledge CLI는 stdout 인코딩을 유지하면서 미지원 문자만 `?`로 대체하도록 설정해 원본과 색인에 영향을 주지 않고 출력 중단을 방지했다. 실제 `PYTHONIOENCODING=cp949:strict` 검색과 전체 회귀 검증에서 종료 코드 0을 확인했다. 로컬 생성물은 경로를 제한해 Git에서 제외하고 Android 실제 소스는 향후 추적 가능하게 유지했으며 모든 기존 파일을 보존했다. 기존 52개 Python 파일은 범위 밖이라 자동 포맷하지 않고 테스트 기록에서 기존 저장소 문제로 구분했다. 별도 저장소의 추적 소스 31개만 해시 검증 후 통합하고 개인 Vault·작업 데이터·로그·가상환경은 제외했다. 기본 데이터 경로를 앱 기준으로 고정하고 예약 작업을 공식 스크립트로 전환했으며, 두 Vault 파일 해시와 Git 동기화 환경값이 변하지 않았음을 확인했다. AutoKnowledge 앱 파일은 별도 Ruff formatter 검사를 통과했고 기존 52개 파일은 범위 밖으로 기록했다. Android와 서버에 동일한 6개 폴더 허용 목록을 적용하고 누락 시 `00_Inbox`로 호환 처리했으며, 서버에서 허용 목록·정규화 경계·심볼릭 링크 경계를 다시 검증했다. 선택값 전달 결함을 수정한 뒤 집중 테스트와 전체 테스트를 재실행했고, 앱 테스트 명령은 앱 프로젝트 디렉터리로 한정했다.
