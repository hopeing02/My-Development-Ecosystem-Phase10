# 오늘 작업

프로젝트별 사용법 문서를 `docs/15_projects/<project>/usage/`에서 관리하도록 표준과 새 프로젝트 생성 템플릿을 확장했다. AutoKnowledge Lite에 사용법 진입 문서를 추가하고 개인 Vault에 6개 카테고리 안내 폴더를 생성했다. 프로젝트 생성 집중 테스트 19개와 전체 회귀 테스트 144개를 통과했고, 개인 Source 증분 스캔과 기본 검색 제외를 확인했다. Windows CP949 콘솔에서 Knowledge 검색 결과의 미지원 Unicode 문자 때문에 발생하던 출력 중단을 수정하고 CP949·UTF-8 회귀 테스트를 추가했다. 전체 테스트 146개와 Ruff·formatter 검사를 통과했다.

# 문제점

프로젝트 공식 설계·구현·테스트·사용법과 개인 학습·생활 자료의 저장 경계가 명확하지 않았고, 기존 개인 노트를 일괄 이동하면 링크와 Git 이력이 깨질 위험이 있었다. 표준 Ruff 명령이 로컬 의존성 폴더 `.test-deps`까지 검사해 외부 패키지 오류 442건을 보고했다. CP949 stdout이 em dash를 인코딩하지 못해 색인과 검색이 성공한 뒤 CLI 출력에서 `UnicodeEncodeError`가 발생했다.

# 해결

프로젝트 공식 기록은 프로젝트 문서 트리에 유지하고 개인 Vault는 같은 개인 보안 경계 안에서 폴더로만 분류하도록 결정했다. 기존 `AutoKnowledge/` 노트 17개는 이동하거나 수정하지 않고 SHA-256 일치로 보존을 확인했다. Ruff는 `.test-deps` 제외 검사와 변경 파일 포맷 검사로 이번 변경이 통과함을 분리 검증했다. Knowledge CLI는 stdout 인코딩을 유지하면서 미지원 문자만 `?`로 대체하도록 설정해 원본과 색인에 영향을 주지 않고 출력 중단을 방지했다. 실제 `PYTHONIOENCODING=cp949:strict` 검색과 전체 회귀 검증에서 종료 코드 0을 확인했다.
