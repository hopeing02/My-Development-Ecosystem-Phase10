# SDS-002 — 승인 보충 원고 기반 확장판

- 문서 번호: ebook_ai/SDS-002
- 버전: 0.1.0
- 상태: Review
- 작성일: 2026-10-26
- 작성자: Codex
- 변경 이력: STEP 02 입출력·보존·검증 계약 최초 작성.
- 목적: STEP 01 렌더링과 출력 내용을 보존하면서 선택적 확장판을 조립한다.

## 기존 구현 재사용

기존 [SDS-001](SDS-001-ebook-assembly.md)의 `_read_manifest`, `_title`,
`_markdown_text`, `BuildResult`와 `build_ebook` 내부 렌더링을 사용한다.
기존 입력 목록·원고·앵커 생성 규칙은 바꾸지 않는다.
실제 목록은 `title`·`chapters[{title,path}]`이며 별도 STEP ID 필드가 없다.
첨부 문서의 `approved-chapters.json`과 `STEP-01`은 추정된 예시다.
현재 원고 목록 이름은 그대로 두고 기존 `chapter-NNN` 앵커를 보충 연결 키로 사용한다.

## 입출력과 API

기존 함수에 keyword-only `supplements_path: str | Path | None = None`을 추가한다.
기존 반환형과 세 필드는 유지한다. CLI는 `--supplements JSON`을 선택적으로 받는다.
별도 CLI·파서·클래스·라이브러리·DB·AI API를 추가하지 않는다.

새 입력은 `{"supplements":[{"step":"chapter-001","path":"supplements/first.md"}]}`다.
목록은 한 항목 이상이어야 하며 JSON/UTF-8 BOM을 지원한다.
`step`은 현재 원고 목록에서 생성되는 실제 장 앵커이며 중복을 거부한다.
`path`는 기존 manifest 폴더 기준 상대경로만 허용한다.
Windows/POSIX 절대경로, drive-relative·UNC·ADS, `..`, 루트 밖으로 resolve되는
심볼릭 링크·junction, 비 MD·누락·빈 파일·비 UTF-8, 입력/보충 파일 재사용을 거부한다.
파일 경로·하드링크의 중복은 `samefile`로 확인한다.
승인은 사용자가 이 별도 목록에 명시하는 것으로 표현하며 자동 판정·검색·AI 작성은 없다.

## 생성과 보존

모든 입력을 검증한 후 기존 함수가 생성하는 같은 장별 텍스트 조각을 기본판과 확장판에 쓴다.
확장판에만 해당 장 뒤 `### 추가 해설`과 승인 보충 원고를 첨부한다.
해설이 없는 장에는 제목을 추가하지 않는다. 기존 기본판 목차·장 제목·앵커는 그대로다.
기존 `toc.md`는 기본판을 가리키며 확장판은 동일한 내부 목차와 앵커를 사용한다.

보충 목록을 주지 않으면 STEP 01의 생성·덮어쓰기·반환·출력 계약을 유지한다.
확장 모드에서는 기존 toc/basic 바이트가 예상 기본판과 같으면 읽기만 하고 보존한다.
다르면 덮어쓰기 옵션과 관계없이 오류다. 파일이 없는 경우 기존 렌더링으로 생성한다.
확장 모드에서 `overwrite=True`는 expanded.md만 교체한다.
출력이 입력 파일 또는 다른 출력과 같은 파일/하드링크이거나 심볼릭 링크면 거부한다.
검증 실패 시 기존 세 출력과 원고를 모두 보존한다.

확장판은 출력 폴더의 임시 파일에 UTF-8/LF로 저장한다.
기본 저장은 완성된 임시 파일을 `os.link`로 배타 게시하고, 덮어쓰기는 `os.replace`로
원자 교체한다. 실패 시 임시 파일을 정리한다. 로컬 하드링크 지원이 필요하다.
다중 파일 트랜잭션과 외부 프로세스의 입력 변경 감지는 이 STEP 범위가 아니다.
입력 원고의 상대 이미지·링크·Markdown 문법 검증 및 충돌 앵커 검사는 STEP 01과 같다.

## 자체 검토

기존 입력/기본판 계약, 별도 승인 입력, 경로 경계, 오류 시 보존과 재현성을 정의했다.
불필요한 추상화와 MDE 핵심 변경은 없다. 승인되지 않은 실제 원고를 사용하지 않는다.
관련 검증과 실행 명령은 [EBOOK-AI-02](../implementation/EBOOK-AI-02.md)에 기록한다.
