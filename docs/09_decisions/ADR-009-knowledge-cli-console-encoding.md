# ADR-009 Knowledge CLI 콘솔 인코딩 오류 대체 정책

- 상태: Accepted
- 작성일: 2026-07-23

## 배경

Windows 기본 PowerShell 환경의 stdout 인코딩이 CP949일 때 Markdown 제목이나 검색 문맥에 em dash 같은 미지원 Unicode 문자가 포함되면 `UnicodeEncodeError`가 발생해 정상 검색 결과 전체가 중단됐다. 색인과 검색 자체는 성공했지만 CLI 출력 경계에서 실패했다.

## 결정

- Knowledge CLI 실행 시작 시 stdout의 기존 인코딩은 변경하지 않는다.
- stdout이 `reconfigure`를 지원하면 `errors="replace"`를 적용한다.
- 현재 인코딩에서 표현할 수 없는 문자만 `?`로 대체한다.
- 원본 문서, SQLite 원문, 검색 결과 객체는 수정하지 않는다.
- stdout을 재구성할 수 없는 테스트·임베디드 스트림은 기존 동작을 유지한다.
- 정확한 Unicode 표시가 필요하면 사용자가 `PYTHONIOENCODING=utf-8`을 명시할 수 있다.

## 결과

한글 등 CP949 지원 문자는 그대로 출력되고, 미지원 기호 때문에 명령이 실패하지 않는다. 화면에 대체된 문자가 있더라도 로컬 색인과 원문에는 영향이 없다.

## 대안

CLI 전체를 무조건 UTF-8로 변경하는 방식은 기존 콘솔과 리다이렉션 소비자의 인코딩 기대를 바꿀 수 있어 채택하지 않았다. 모든 문자를 수동 치환하는 방식은 지원 범위를 지속해서 관리해야 하므로 채택하지 않았다.
