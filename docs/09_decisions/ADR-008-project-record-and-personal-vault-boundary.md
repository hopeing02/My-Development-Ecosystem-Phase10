# ADR-008 프로젝트 기록과 개인 Vault 분류 경계

- 상태: Accepted
- 작성일: 2026-07-23

## 배경

프로젝트 설계·구현·테스트·사용법과 개인 학습·생활 자료를 같은 위치에 저장하면 공식 문서의 단일 원본이 불명확해지고 개인 자료가 프로젝트 Git 저장소에 포함될 수 있다. 개인 Vault 안에서도 같은 보안 경계를 가진 노트를 주제별로 찾기 쉬운 분류가 필요하다.

## 결정

- 프로젝트 공식 문서는 `docs/15_projects/<project>/`를 단일 원본으로 사용한다.
- 프로젝트별 설치·실행·기능 사용법은 `docs/15_projects/<project>/usage/`에 저장한다.
- 기능 추가·정정 구현 기록은 `implementation/`, 테스트는 `tests/`, 버전 기록은 `releases/`와 루트 `CHANGELOG.md`에 저장한다.
- 원시 실행 로그와 임시 데이터는 Git 제외 경로에 두고, 재사용 가능한 분석 결과만 프로젝트 문서로 요약한다.
- 개인 Vault는 하나의 `personal` Source와 개인 Git 저장소를 유지하면서 폴더로 주제를 분류한다.
- 개인 Vault의 기본 폴더는 `00_Inbox`, `10_Life`, `20_Learning`, `30_Interests`, `40_Reference`, `90_Archive`로 한다.
- 기존 `AutoKnowledge/`는 자동 수집 원본 보존 영역으로 유지하며 기존 노트를 자동 이동하거나 수정하지 않는다.
- Source Category와 Vault 내부 폴더 Category는 다른 개념이다. 전자는 보안·검색 범위를, 후자는 같은 개인 보안 경계 안의 주제를 나타낸다.

## 결과

프로젝트 공식 기록은 코드와 함께 추적되고, 개인 자료는 외부 민감 Vault에 남는다. 기존 개인 노트는 보존하면서 새 노트부터 분류 체계를 적용할 수 있다.

## 대안

개인 노트를 프로젝트 폴더에 함께 저장하는 방식은 개인정보와 공식 문서 경계가 섞이므로 채택하지 않았다. 기존 노트를 일괄 이동하는 방식은 링크와 Git 이력을 깨뜨릴 수 있어 채택하지 않았다.
