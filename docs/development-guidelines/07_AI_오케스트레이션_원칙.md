### AI 오케스트레이션 확장 준비 원칙

**1. 기본 방향**
- 현재 개발은 AI 없이 독립 실행 가능한 구조를 유지한다.
- 향후 인터넷판에서는 Python 기반 AI 오케스트레이션을 도입할 수 있도록 설계한다.
- AI 오케스트레이션을 위한 불필요한 기능을 미리 구현하지 않는다.

**2. 기존 기능 재사용**
- 기존 검증 완료 함수와 알고리즘을 최우선으로 재사용한다.
- 기능별 입력값, 출력값, 실행 결과, 오류 정보를 명확히 정의한다.
- 향후 AI 연결은 기존 함수를 변경하기보다 Adapter를 통해 수행한다.

**3. 업무 로직과 실행 제어 분리**
- 업무 처리 로직과 작업 실행 순서를 가능한 범위에서 분리한다.
- 기존 Service·Repository·Storage 구조를 유지한다.
- AI 호출 및 작업 분배 기능은 실제 필요성이 확인된 시점에 추가한다.

**4. AI 도입 단계**
- 1단계: 기존 Python Workflow 재사용
- 2단계: 단일 AI 기능 연결
- 3단계: Python 경량 오케스트레이터 도입
- 4단계: 복잡한 다중 AI 협업이 필요할 때 LangGraph 등 검토

**5. 내부망·인터넷판 분리**
- 내부망 VBA 시스템은 AI 없이 독립 실행한다.
- 인터넷판 AI 기능은 별도 서비스로 구축한다.
- 기관의 승인 없이 내부망 소스 코드, 업무자료, 민감정보를 외부 AI에 전달하지 않는다.

**6. 과설계 방지**
- AI 에이전트, Workflow Engine, 공통 Framework 등을 사전에 대규모로 구축하지 않는다.
- 여러 프로젝트에서 실제로 재사용할 필요가 확인된 기능만 공통화한다.
- 기존 검증 코드의 불필요한 재작성과 리팩터링을 금지한다.
