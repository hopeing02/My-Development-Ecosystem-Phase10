\[AI 코드 생성 규칙\]

1\. 기존 검증 완료 코드는 수정·재작성하지 않는다.

2\. 기존 함수로 구현 가능한 경우 반드시 기존 함수를 재사용한다.

3\. 신규 Function/Sub 생성은 최소화한다.  
   \- 단순 편의를 위한 Helper 함수 생성 금지  
   \- 한 번만 사용하는 짧은 Wrapper 함수 생성 금지  
   \- 불필요한 추상화 금지

4\. 신규 함수가 반드시 필요한 경우:  
   \- 함수명은 역할이 바로 보이게 작성  
   \- 한 함수는 한 가지 역할만 담당  
   \- 호출 단계를 불필요하게 깊게 만들지 않는다.  
   \- 기존 프로젝트에서 사용 중인 문법과 패턴을 우선 사용한다.

5\. 새로운 VBA 문법·라이브러리·객체 사용을 최소화한다.  
   기존 프로젝트에서 이미 검증한 방식이 있으면 그것을 재사용한다.

6\. AI가 임의로 Architecture/Pattern을 추가하지 않는다.  
   \- Factory  
   \- DI  
   \- 과도한 Interface  
   \- 범용 Helper 계층  
   등은 명시적으로 요청하지 않는 한 추가하지 않는다.

7\. 코드 작성 후 반드시 표시한다.  
   \[기존 재사용 함수\]  
   \[신규 함수\]  
   \[수정 함수\]  
   \[신규 함수가 필요한 이유\]

8\. 오류 수정 시 전체 구조를 다시 설계하지 않는다.  
   최초 오류 발생 지점을 기준으로 최소 수정한다.

9\. 오류 수정 과정에서 신규 함수를 추가하지 않는다.  
   신규 함수가 반드시 필요하면 코드를 작성하기 전에 이유를 설명한다.

10\. 사람이 직접 디버깅하기 쉬운 코드를 우선한다.  
    코드 길이 감소보다 가독성·추적 가능성을 우선한다.
