네. 이건 앞으로 오토리 설계의 **최상위 원칙**으로 두는 게 좋습니다. 특히 회사 내부망에서 쓰는 시스템이라면 기능보다 보안을 먼저 제한해야 합니다.

핵심은 **"오토리는 회사 시스템을 우회하거나 대량 복제하는 프로그램이 아니라, 내가 정상적으로 접근 권한을 가진 자료를 검색·색인·연결하는 개인 업무도구"** 로 만드는 것입니다.

### **보안 기준을 이렇게 잡겠습니다**

| 영역 | 원칙 |
| ----- | ----- |
| 접근권한 | 사용자가 원래 접근 가능한 자료만 처리 |
| 인증 | ID·비밀번호·OTP를 VBA에 저장하지 않음 |
| 사이트 감시 | 인증 우회·세션 탈취·보안통제 우회 금지 |
| 자동수집 | 회사 정책상 허용된 페이지/자료만 |
| 원문 | 필요 이상으로 복제하지 않고 가능하면 링크·ID·메타데이터 중심 |
| 개인정보 | 주민번호·계좌번호 등은 색인/Content 저장 최소화 또는 제외 |
| 외부전송 | 회사 자료를 외부 AI·클라우드·개인 PC로 전송하지 않음 |
| 로그 | 언제 무엇을 수집·갱신했는지 기록 |
| 삭제 | 원본 삭제·수정 없이 오토리 데이터만 관리 |
| 변경감지 | 원본을 수정하지 않는 **Read-Only** 방식 |

특히 변경감지도 다음 구조로 만들면 안전합니다.

회사 사이트  
    │  
    │ 읽기만  
    ↓  
\[변경감지 Adapter\]  
    ↓  
제목 / URL / 문서ID / 수정일 / Hash  
    ↓  
오토리

예를 들어 회사 사이트의 매뉴얼이 바뀌었다고 해서 매번 원문 전체를 가져올 필요도 없습니다.

SourceId  
SourceURL  
Title  
LastCheckedAt  
LastModifiedAt  
ContentHash  
Status

정도만 가지고 있다가,

기존 Hash \= ABC123  
현재 Hash \= DEF456  
             ↓  
          CHANGED

로 표시하는 방식입니다.

그리고 **Hash조차 원문을 회사 밖으로 보내는 것이 아닙니다.** 내부 PC에서 계산해서 결과값만 저장하면 됩니다.

### **한 가지는 반드시 구분해야 합니다**

회사 보안정책상 자동접속 자체가 금지된 사이트가 있을 수 있습니다. 그런 사이트까지 Selenium 등으로 억지로 자동화하지 않겠습니다.

그 경우에는 오토리가:

\[재확인 필요\]  
법인세 업무매뉴얼  
마지막 확인: 2026-09-01

→ 원본 사이트 열기  
→ 확인 완료

까지만 담당하도록 하면 됩니다.

즉 **자동화 가능 영역과 보안상 사람이 확인해야 하는 영역을 분리**하는 겁니다.

그리고 기존 회사 사이트는 말씀하신 것처럼 사실상 **원본 창고(Source)** 로 남겨두고,

             \[오토리\]  
                 │  
      ┌──────────┼──────────┐  
      ↓          ↓          ↓  
   세법 원본    사내사이트    공유폴더  
      │          │          │  
      └──────────┼──────────┘  
                 ↓  
        검색 · 관계 · 색인  
        변경감지 · 매뉴얼  
        체크리스트 · 업무연결

로 만드는 것이 좋습니다.

이렇게 하면 회사 데이터를 마음대로 긁어 모으는 시스템이 아니라 **기존 보안권한을 그대로 존중하면서 그 위에 개인 지식 탐색 계층을 하나 올리는 구조**가 됩니다.

앞으로 오토리 기능을 설계할 때도 **① 원본 무수정 → ② 권한 우회 금지 → ③ 외부전송 금지 → ④ 최소 데이터 저장 → ⑤ Read-Only 우선 → ⑥ 로그 기록**을 기본 보안 원칙으로 적용하겠습니다.
