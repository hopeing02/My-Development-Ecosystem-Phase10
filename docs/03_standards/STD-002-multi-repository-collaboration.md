# STD-002 다중 저장소 협업 표준

## 1. 목적

MDE를 2~3명의 사용자가 여러 프로젝트에서 공동으로 사용할 때 필요한 저장소, 브랜치, 작업 소유권, 검증 규칙을 정의한다.

## 2. 저장소 구성

- `mde-core` 저장소는 MDE CLI, Agent, Workflow, Template을 관리한다.
- 실제 제품은 각각 독립된 Git 저장소로 관리한다.
- 각 제품 저장소 루트에는 `.mde/project.yaml`을 둔다.
- 제품 소스나 비밀정보를 `mde-core` 저장소에 복제하지 않는다.

## 3. 브랜치와 Pull Request

- 기본 브랜치는 `main`이다.
- `main`에는 직접 commit 또는 push하지 않는다.
- 작업 브랜치는 `<type>/<assignee>/<task-id>` 형식을 사용한다.
- 모든 변경은 Pull Request와 최소 1명의 승인을 거쳐 병합한다.
- GitHub Ruleset을 최종 강제 수단으로 사용하고 MDE CLI는 로컬 사전 검증을 담당한다.

## 4. 작업 소유권

- 모든 작업 YAML에는 GitHub 사용자명과 일치하는 `assignee`를 기록한다.
- 작업 브랜치의 담당자 구간은 작업 YAML의 `assignee`와 일치해야 한다.
- 하나의 작업에는 한 명의 주 담당자를 지정한다.

## 5. 프로젝트 명령

- 테스트와 빌드 명령은 `.mde/project.yaml`에서 프로젝트별로 정의한다.
- MDE는 명령을 선언된 순서대로 실행하고 하나라도 실패하면 성공으로 처리하지 않는다.
- 빈 명령, 쉘 제어 연산자를 포함한 명령, 프로젝트 루트 밖에서의 실행은 허용하지 않는다.

## 6. 완료 조건

- 작업 담당자와 브랜치가 검증된다.
- 프로젝트에 선언된 테스트와 빌드가 통과한다.
- Pull Request 필수 검사가 성공한다.
- 승인 후 `main`에 병합된다.
